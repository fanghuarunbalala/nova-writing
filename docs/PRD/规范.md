# PRD 文档规范

- PRD 文档统一放在 `docs/PRD/`：整体产品 PRD 为 `产品总览.md`；功能级 PRD 一功能一文件，命名 `<模块>-<功能>.md`（如 `compose-审批流.md`）。
- 新功能先写 PRD 再动工：从 `_模板.md` 复制起步，固定章节（背景与目标 / 用户故事 / 流程图 / 功能明细 / 边界与非目标 / 验收标准 / 开放问题）不得删减。
- **流程图必填**：主流程用 Mermaid `flowchart`，多主体交互用 `sequenceDiagram`，状态流转用 `stateDiagram`；关键流程必须有图，禁止仅用文字描述流程。
- 功能明细逐点写清：触发条件 / 输入 / 处理逻辑 / 输出 / 异常与回退。
- 状态标记与 architecture.md 对齐：⏳ 待敲定 → ✅ 已定稿；定稿后技术实现回填 `../architecture.md`。
