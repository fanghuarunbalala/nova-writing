## 1. 背景与问题

### 1.1 配对错位（管线粒度问题）

现行管线：**整章**正文 → LLM 提炼**章级**五要素 → 扩写**整章** → 切窗 → 原文窗与 AI 窗**按章内索引 zip 配对**。标注页上"配对窗 N"的两栏是章内不同位置、不同场景的切片，"同一大纲的执行差距对比"在窗级不成立；⚡ 预标同样标在两块不相关文本上。

### 1.2 标注页形态与管线脱节（本次新增，用户提出）

现行标注页是**并排双栏**（原文 | AI 扩写）同屏标注，存在三个问题：

1. **看不到中间产物**：管线的真实链路是 `原文 → 窗口概要 → 生成`，但概要（五要素）在标注页上不可见——标注者无法对照"生成内容是否覆盖了概要要素"，也就难以判"空泛/解说"这类执行缺陷；
2. **对比偏置**：并排同屏标两栏，判分天然变成"相对比较"（AI 比原文差/好比原文好），而训练目标是**绝对判分**（该段本身有没有缺陷）；
3. **信息过载**：同屏 2×8 段 × (7 胶囊+情绪+证据) 的控件密度高，移动端更甚。

### 1.3 LLM 通道不可配置

所有 LLM 调用（提炼/扩写/预标）依赖服务端环境变量，网页无法查看、配置或切换 provider，换 key/换模型要改环境并重启。

### 1.4 界面桌面优先

≤720px 窄屏下标注表格横向溢出、导航点按困难；局域网访问能力已有（`--host 0.0.0.0`）但页面未适配。

## 2. 目标 / 非目标

**目标**

1. 配对生成改为**窗口级**：每原文窗独立走「该窗正文 → LLM 提炼窗口概要（五要素）→ 扩写 → 恰好一个生成窗」，1:1 内容对齐；
2. 标注页按管线形态重构为**两段式**：第 1 部分标原文窗，第 2 部分标"概要 + 生成窗"，概要作为只读中间产物呈现；
3. 工作台网页可配置 LLM provider（baseUrl / API key / 生成模型 / 标注模型），保存即时生效，带测试连接；
4. 全部页面移动端（≤720px）可用；主题浅色精修默认 + 暗色可切。

**非目标**

- 不改标注 schema（labels v2 冻结）；
- 不动训练侧（train/weights/infer/embed）；
- 不做多用户与鉴权（单人 last-write-wins）；
- 不做窗口概要的网页编辑（提炼即用；单窗重提列为后续项 O7）；
- 独立批次（题目注入）的单栏标注页不动（本无对照问题）。

## 3. 术语

| 术语 | 含义 |
|---|---|
| 原文窗 | 从真实书正文切的窗口（≤8 段，`source="book"`） |
| 窗口概要 | 从**该原文窗**提炼的五要素（人物/地点/事件/转折/情绪），扩写的唯一信息源 |
| 生成窗 | 从窗口概要扩写出的 AI 文本（恰好一个窗，`pairWindowId` 指回原文窗） |
| 两段式标注 | 每窗标注分两部分：① 标原文窗；② 标生成窗（概要同屏只读） |
| pair | 一个原文窗 + 其生成窗的配对单元（标注进度与保存的最小整体） |

## 4. 总体流程（改造后）

```
真实书（book.json）
  → 建窗（现有，自适应 ≤8 段/窗）
  → 每原文窗：
      ① LLM 提炼窗口概要（五要素，≤100 字/要素防泄漏护栏）
      ② LLM 扩写（目标行数=该窗段数；只见概要+风格锚，永不见原文）
      ③ 生成窗记录（pairWindowId 指回原文窗，单窗不切片）
  → 两段式标注页：第1部分 标原文窗 → 第2部分 标（概要+生成窗）
  → labels-<scope>.jsonl（训练管线直接读）
  → embed + train（不变）
```

## F1 窗口级配对生成管线（替换整章配对）

**入口**：书页（原生成页改造）新增「窗口级配对生成」：选章（多选）→ 执行 → 进度与预览。

**执行逻辑**（`Workbench.generate_window_pairs(alias, chapters)`）：

- 读 `<alias>-windows.jsonl` 中所选章的 `source="book"` 原文窗，逐窗：
  1. `extract_outline(章标题+窗序, join(texts))` —— 复用 `outline.py`（防泄漏截断不变）；
  2. `expand_unit(概要, target_lines=len(texts), style_anchor=书风格锚, form=按书)` —— 复用 `expand.py`（空/过短重试不变）；
  3. 生成窗记录：`windowId = <alias>-ai-<原窗后缀>`（如原文 `wudao-c002-w001` → `wudao-ai-c002-w001`）；**`pairWindowId` = 原文窗 windowId**；**单窗构造**（整段列表直接成一条记录，不走 8 段滑窗——AI 段数 ≠ 8 不切片）。
- **幂等**：重跑所选章 = 整章替换该章生成窗（按 `chapterNo` 覆盖，不追加）；
- **成本**：每窗 2 次 LLM 调用（提炼+扩写），一章约 15 窗 ≈ 30 次；
- **溯源**：窗口概要存 `training/artifacts/<alias>-window-outlines.json`：`{schema:1, book, generatedAt, windows: {windowId → {title, elements, model}}}`（gitignored）；
- **移除**：生成页「对照章」下拉与整章仿写配对路径删除；章级大纲向导保留（供独立仿写批次用）；预览区抽查「原文窗 → 概要 → 生成」三方对应。
- **存量**：整章级 ai-windows 作废重生成（现人工标注仅 1 窗，作废口径同 v2 迁移）。

## F2 两段式标注页（核心重构，用户需求）

### F2.1 页面结构（每个 pair 一屏内两步）

```
┌─────────────────────────────────────────┐
│ 配对标注 · wudao   [3/45] [命中统计] [导出] │ ← 顶栏不变
├─────────────────────────────────────────┤
│ 步骤指示： ①标原文 ─── ②标生成    (当前①) │ ← 两段进度
├─────────────────────────────────────────┤
│ 【第 1 部分 · 原文窗】 wudao-c002-w001    │
│  原文段落（≤8 段，每段：文字 + 7 缺陷胶囊  │
│  + 情绪 0-3 单选 + 证据输入）             │
│  [全零] …… 控件与 schema v2 完全一致      │
│                                         │
│         [ 下一步：标生成内容 → ]          │ ← 本部分完成确认
├─────────────────────────────────────────┤
│ 【第 2 部分 · 概要 + 生成窗】（下一步展开） │
│  ┌─ 窗口概要（只读卡，可折叠）──────────┐  │
│  │ 人物：… 地点：… 事件：… 转折：… 情绪：…│  │ ← 中间产物呈现
│  └─────────────────────────────────────┘  │
│  生成段落（每段控件同上）wudao-ai-c002-w001 │
│  ‹ 查看原文（默认折叠，展开供对照）         │
│                                         │
│         [ ‹ 回原文 ]  [ 保存并下一窗 › ]   │
├─────────────────────────────────────────┤
│ 底部导航：‹ 上一窗 跳过 ☰概览 ⚡预标 ⚑存疑  │ ← 不变
└─────────────────────────────────────────┘
```

### F2.2 交互规则

- **步骤进入**：默认进入第 1 部分；点「下一步」时校验原文侧（判 1 缺证据/情绪未选的确认弹窗与现行为一致）→ 记住原文侧当前勾选状态（仅前端暂存）→ 展开第 2 部分；
- **保存语义**：「保存并下一窗」= **整窗两部分一起落库**（两条记录：原文窗 + 生成窗，schema 与现有一致：labels/emotion/evidence/meta）；第 1 部分未完成时点击 → 提示"原文侧未标注完成"并允许「确定=按当前状态保存」；
- **独立判分原则**：第 2 部分默认**不显示原文**（只显示概要 + 生成内容）——与生成条件同构（生成时也只见概要），避免对比偏置；「查看原文」为折叠开关，展开不影响已作的判分；
- **概要卡**：只读、默认展开、可折叠；显示五要素与提炼模型；是判"生成是否覆盖要素"的对照物；
- **⚡ 预标**：按当前所在部分预填（第 1 部分预标原文窗、第 2 部分预标生成窗），逐窗一次调用不变；
- **概览/导出/存疑/跳过/全零**：沿用现有语义；概览格状态增加中间态——`未开始` / `原文已标`（半程）/ `整窗完成`（绿）；跳过 = 不落库直接下一窗（与现行为一致）；
- **进度与统计**：pairTotal/pairDone 按显式映射计算；命中统计聚合两部分记录。

### F2.3 移动端（≤720px）

- 两部分纵向单列；步骤指示吸顶；段落卡片化（demo 已确认形态）：文字在上、胶囊换行、情绪一行、证据入卡；
- 底部拇指导航 ≥44px；「下一步/保存」主按钮固定底部主位。

### F2.4 桌面端（>720px）

- 保持单列两段式（不再并排双栏）——判分独立性与控件密度均优于双栏；宽度用于段落卡内文字与胶囊的舒展（内容最大宽度 ~900px 居中）。

## F3 LLM Provider 配置

- **存储**：新 `prose_gate/config.py` 读写 `training/artifacts/workbench-config.json`（gitignored，本机明文——单人本地工具可接受，UI 注明）：`{baseUrl, apiKey, model, judgeModel}`；
- **优先级**：config > 环境变量回退（`annotate.resolve_*` 现有链）> 报错；测试注入 fake LLM 最高（`make_server(llm_call=...)` 不变）；
- **协议**：OpenAI 兼容 `/chat/completions`（deepseek / GLM / openrouter / ollama 等通用）；
- **分工**：窗口概要提炼 / 扩写 = **生成模型** `model`；⚡ 预标 = **标注模型** `judgeModel`；
- **生效**：Workbench 每次调用动态读 config，网页保存即时生效免重启；
- **UI**（demo 已确认样式）：首页设置面板——baseUrl、API Key（**掩码回显，只写不回读**）、生成模型、标注模型 + 保存 + 测试连接（一次小调用回显模型名/耗时/首句）；
- **API**：`GET /api/config`（key 掩码）/ `PUT /api/config` / `POST /api/config/test`。

## 7. 交互细节与边界

- **防泄漏**：概要要素 ≤100 字截断（`outline.parse_outline_reply` 既有）；扩写只见概要+风格锚；
- **空窗与重试**：扩写空/过短重试沿用（max 3 次取最长）；整章重跑幂等替换；
- **旧数据兜底**：ai-windows 无 `pairWindowId`（章级遗留）→ 不进新标注页进度，页头提示"该章为章级旧数据，请重跑窗口级生成"；zip 兜底仅保留给独立测试用途；
- **表单校验**：判 1 缺证据、情绪未选的确认弹窗语义沿用（每部分各自校验）；
- **进度持久化**：labels 实时落盘（现有原子写）；第 1 部分完成但整窗未保存时，刷新后按"原文已标"中间态恢复（前端从已存记录推断，未存则重标该部分）；
- **概览中间态**：`原文已标` 判定 = 该 pair 的原文窗记录已落库而生成窗记录未落库。
