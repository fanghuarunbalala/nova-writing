# 域模型规范（大纲 / 卷章 / 段落）

> 域概念边界的唯一规范：工具 desc/schema、prompt 段、PRD、store 实现一律遵守。
> 关联：`docs/PRD/library-完本解构.md`（书库全景，概念澄清一节）；工具面 `core/src/runtime/tool/definitions/novel.ts`。

1. **三层概念各自独立**：
   - **大纲（story_unit）= 叙事单位**：saga（全书根）→ arc（叙事弧）→ sequence → scene 的层级树；**幕（scene）是叙事原子粒度**，承载时间、地点、人物、事件（经 `intent`/`synopsis` 与 leaf 计划表达：人物/地点绑定、事件序列、实体状态变更）。大纲是整本书的结构真相源。
   - **卷/章（volume/chapter）= 发布单位**：章按 `paragraphIds` **有序选择**段落组装正文（可跨单元、可拆分/合并/重排）；卷是发布容器。发布结构只「选材」，不「拥有」正文、不定义故事结构。
   - **段落（paragraph）= 正文唯一载体**：挂 scene 级单元（`storyUnitId`）；创作库语义下不可变追加、修改走 Edit。

2. **幕与章/卷无结构对应**：一章可含多幕、恰好一幕、或**一幕半**（章尾钩子停在幕中）；一个 arc 可跨多卷，一卷也可含多个 arc。禁止任何实现、表述或示例暗示 arc↔卷、scene↔章 的 1:1 或包含关系。

3. **映射只走弱关联**：幕↔章映射仅允许两种表达——章 `storyUnitId`（**仅来源提示**语义，创建时可带、之后不可改）与两侧说明文本（synopsis/intent 等）内的显式引用。不得新增结构性强关联字段。

4. **禁止用发布词义定义叙事层级（含反向）**：scope 枚举、kind 描述、示例中不得出现「arc=卷级弧」「章级场景」这类跨层耦合表述；arc 的跨度由故事节奏决定，与卷的划分无关。反向同理：不得用叙事词义定义发布单位（如「卷=大高潮」）。

5. **关系只记在大纲**：人物/地点档案本体无关系字段；人物↔人物、人物↔地点的关联与演变只记录在 scene 的 leaf 计划（绑定 + 实体状态变更）。查关联读大纲，不查档案。

6. **表述与快照联动**：修改工具 desc/schema 中涉及本规范的文本，必须同步更新 evals Tier 0 金样快照（desc/schema 金样），并在 PR 变更说明中标注触发的条目编号。
